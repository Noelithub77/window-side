01 Why

Dual boot is a wall.

Your Windows apps live on the other side of a reboot. Every trip closes your terminal, your browser and whatever you were doing. A fresh virtual machine skips the reboot, but then you keep two copies of Windows, two sets of apps and two lots of updates.

02 The name

A window in the wall.

window-side keeps Windows at the side of your Linux desktop, like the seat by a window: you stay where you are, and the view is right there.

The mark is that window. Four panes, and the lighter one swings open onto Windows.

03 How it works

One install.
Two ways in.

Booting Windows natively still works exactly as before. window-side adds a second door: KVM, the virtual machine built into the Linux kernel, starts that same Windows with the cores and memory you give it. If Windows has a drive of its own, the VM gets the whole drive. If it shares a drive with Linux, window-side joins a small copy of the boot files to the Windows partition, so the VM never sees your Linux partitions.

05 First boot

Familiar first.
Fast after.

Windows can’t read a VirtIO disk, the fast virtual hardware KVM prefers, until it has the drivers. So the first boot uses a plain SATA disk and network card that Windows already knows. You install the guest tools from a driver CD, the one manual step, and window-side switches to VirtIO and waits for the guest agent to answer.

Nothing is marked done until the guest agent answers on the new hardware. A failed switch restores the saved SATA definition after checking it is the same disk.

06 Display

Three ways to look.

Run Windows headless for agents and background jobs, open a console when you want the desktop, or give it a real graphics card and watch through Looking Glass. Windows draws on its own GPU, and Looking Glass copies each finished frame through shared memory into a Linux window, so there’s no video stream and almost no delay.

Looking Glass is an independent open-source project by Geoffrey McRae and contributors. window-side sets up the VM around it and opens it for you.

07 Boot profiles

One GPU, one side
at a time.

A graphics card passed through belongs to Windows completely. window-side adds a GPU entry beside your normal one in the boot loader. The normal profile keeps the card on Linux. The GPU profile reserves it at boot for vfio-pci, a driver that holds it for the VM. Switching is always an explicit reboot.

09 Agents

Give your agent
a Windows.

Every ws command prints JSON. An agent can start Windows, run PowerShell, copy files and use SSH, and read structured results instead of screenshots. Setup itself can be handed to Claude Code, Codex or OpenCode, and the agent stays read-only until you approve the apply.

Ask your agent

Build the Windows release of this app and run its tests.

  1. ws start
  2. ws copy app.zip 'C:\build\app.zip'
  3. ws exec --json '.\build.ps1 -Test'
